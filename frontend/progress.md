## Remaining Path
- 若继续设计：可进入“上线运营策略 / 版本节奏 / 商业化（若未来需要）”
- 若进入执行：可按第 1 周冲刺板直接启动开发
- 若进入开发：可直接按 issue backlog + 实施矩阵拆前后端任务
- 若进入上线准备：可按 launch runbook 执行检查与回退策略
- 若团队需要统一入口：从 delivery index 开始
- 若进入联调：realtime event dictionary 和 memory lifecycle 可直接作为对齐文档
- 若需要并行前后端开发：可直接使用 mock payloads
- 若准备起仓：可直接按 scaffold blueprint 建目录
- 若准备统一失败语义：可直接按 error codes 落地
- 若团队今天就要开工：直接按 kickoff handoff 分工启动
- 若后端要按 Java 服务拆域：直接按 backend blueprint 建模块
- 若团队进入下一阶段：按 phase handoffs 做交接
- 若是第一次进仓库：先看 README，再进 delivery index
- 若团队担心方向反复变化：先看 decisions and assumptions
- 若准备真机验证：先看 compatibility checklist
- 若准备首发节奏与版本迭代：先看 release cadence
- 若担心首发后怎么观察与取舍：先看 launch ops 与 monetization boundary
- 若准备开会统一风险：先看 risk register
- 若准备把剩余模糊点拍板：先看 open questions
- 若要查看本轮人工复核结果：先看 self review
- 若产品/开发/QA 需要统一剧本：先看 user journeys
- 若准备做最小冒烟验证：先看 qa smoke checklist
- 若前后端要统一时序理解：先看 chat sequence 和 realtime sequence
- 若团队术语经常说不一致：先看 glossary
