# 后端托管记忆控制设计

状态：MVP 后递延设计

范围：Sister 桌面宠客户端的记忆可见性、暂停、删除与隐私边界。本文只描述设计，不实现记忆功能，也不把 Memory 所有权移入客户端。

## 1. 设计立场

Sister 的 Memory 由 Java 后端作为唯一事实来源。Redis 短期记忆、MySQL 消息记录、自动摘要、Milvus 长期语义检索都属于后端 Memory 域。客户端只展示后端授权公开的状态，并向后端提交用户意图。

客户端不能直接维护长期记忆索引，不能在本地重建摘要，不能把聊天记录缓存成可检索的独立记忆库。这样可以让聊天、WakeUp 主动唤醒、Peek 屏幕感知、Anchor 情绪锚点、Emotion PAD 状态和 OCEAN 人格都读取同一份受控记忆上下文。

## 2. 用户可见控制

MVP 先保留轻量入口，丰富记忆 UI 递延到后续版本。客户端可见控制建议分为四类。

1. 记忆状态
   展示当前是否允许记忆写入，最近一次摘要时间，长期记忆索引是否可用。只显示后端返回的聚合状态，不显示未授权原文。

2. 暂停记忆
   用户可以暂停新的 Memory 写入。暂停后，聊天仍可继续，但后端不把新对话写入摘要和向量记忆。短期上下文是否保留由后端策略决定，并在状态接口里明示。

3. 删除记忆
   用户可以按范围删除。第一阶段支持删除全部后端记忆，后续可增加按时间、按会话、按主题删除。删除动作必须由后端执行，并返回异步任务状态。

4. 记忆说明
   用短文解释 Sister 会记住什么，记忆如何帮助聊天、WakeUp、Peek 和 Anchor，用户怎样暂停或删除。说明不能承诺客户端本地已经清除后端数据，必须以任务完成事件为准。

## 3. 客户端责任

客户端负责把 Memory 控制做成清楚、可撤回、低打扰的体验。

1. 展示后端状态
   启动设置页、聊天页侧栏、隐私入口时请求记忆状态。展示 `enabled`、`pausedUntil`、`summaryUpdatedAt`、`deleteJobStatus` 等字段。

2. 提交用户意图
   暂停、恢复、删除都通过 API 调用后端。客户端不推断最终结果，只根据后端响应和事件更新 UI。

3. 管理本地瞬时数据
   删除完成后清空当前页面里的消息列表、搜索结果、记忆卡片和临时截图预览。若后端仍在处理，客户端显示处理中，不假装已经完成。

4. 限制 UX 表达
   所有删除与暂停入口都要说明影响范围。暂停记忆不等于匿名聊天，删除记忆不等于撤回已经生成过的模型输出。需要二次确认，但不要用恐吓式文案。

5. 保护隐私表面
   Peek 截图、聊天原文、摘要片段、语义命中内容只在需要时短暂展示。客户端不写入日志，不写入 localStorage，不放入可被第三方脚本读取的全局状态。

## 4. 后端责任

Java 后端负责记忆生命周期和一致性。

1. 统一写入策略
   Chat、WakeUp、Peek、Anchor 相关事件进入 Memory 前，先检查用户记忆策略。暂停期间不生成新的长期记忆，不更新摘要，不写 Milvus。

2. 统一删除策略
   删除任务清理 MySQL 消息记录或记忆记录、Redis 短期上下文、摘要记录、Milvus 向量、图谱实体引用。若部分存储失败，任务状态必须保留失败原因，方便用户重试。

3. 统一读取边界
   `SisterChatService`、WakeUp 生成器、Memory 查询服务都从后端 Memory 服务读取，不从客户端传入的历史记录中信任记忆内容。

4. 事件通知
   后端发布记忆策略变更、删除进度、删除完成、删除失败等事件。客户端用事件刷新 UI，避免轮询成为主要路径。

## 5. API 与事件草案

以下只是接口草案，用于后续后端设计对齐。

```http
GET /api/memory/status
```

返回用户当前记忆状态。

```json
{
  "enabled": true,
  "pausedUntil": null,
  "shortTermPolicy": "backend_managed",
  "longTermIndexReady": true,
  "summaryUpdatedAt": "2026-06-04T10:30:00+08:00",
  "activeDeleteJobId": null
}
```

```http
POST /api/memory/pause
```

请求体示例。

```json
{
  "scope": "new_writes",
  "durationMinutes": 1440,
  "reason": "user_privacy"
}
```

```http
POST /api/memory/resume
```

恢复新的 Memory 写入。

```http
POST /api/memory/delete-jobs
```

请求体示例。

```json
{
  "scope": "all",
  "includeShortTerm": true,
  "includeSummaries": true,
  "includeVectorIndex": true,
  "includeGraphLinks": true
}
```

```http
GET /api/memory/delete-jobs/{jobId}
```

查询删除任务进度。

建议事件名称。

```text
memory.status.changed
memory.pause.started
memory.pause.ended
memory.delete.started
memory.delete.progress
memory.delete.completed
memory.delete.failed
```

## 6. 暂停流程

1. 用户在隐私设置里点击暂停记忆。
2. 客户端展示暂停范围，说明聊天仍会经过后端处理，但不会新增长期记忆。
3. 用户确认后，客户端调用 `POST /api/memory/pause`。
4. 后端写入用户 Memory 策略，发布 `memory.pause.started`。
5. 客户端收到状态后，把记忆状态标为已暂停，并在聊天输入区显示轻量提示。
6. 后端在暂停期间阻止摘要、向量写入和图谱扩展。聊天上下文窗口由后端按策略处理。
7. 到期或用户恢复后，后端发布 `memory.pause.ended`，客户端更新 UI。

## 7. 删除流程

1. 用户从隐私设置进入删除记忆。
2. 客户端展示影响范围：对话记忆、摘要、语义索引、图谱引用、短期上下文。说明删除不会撤回已经播放过的语音或已经显示过的消息。
3. 用户二次确认后，客户端调用 `POST /api/memory/delete-jobs`。
4. 后端创建异步删除任务，立即返回 `jobId`。
5. 客户端显示处理中，禁用重复提交。可通过事件或 `GET /api/memory/delete-jobs/{jobId}` 更新进度。
6. 后端按存储层清理数据，并阻止同一用户在删除任务期间生成新的长期记忆。
7. 删除完成后，后端发布 `memory.delete.completed`。
8. 客户端清空当前可见的记忆面板、搜索结果、聊天历史缓存和临时预览，再重新请求 `GET /api/memory/status`。
9. 如果任务失败，客户端展示后端返回的可读原因和重试入口，不声称数据已删除。

## 8. 隐私边界

1. 后端边界
   记忆存储、检索、摘要、向量索引、删除任务、暂停策略都在后端执行。后端需要保留审计字段，如请求时间、任务状态、失败原因，但审计内容不应包含聊天原文。

2. 客户端边界
   客户端只保留当前会话渲染所需的瞬时状态。刷新页面、退出桌宠、删除任务完成后，应丢弃内存中的可见片段。默认不落盘，不做全文搜索索引。

3. Peek 边界
   Peek 截图属于高敏感输入。客户端只在后端请求时采集，并在发送后释放预览。记忆暂停期间，后端可以继续用截图生成即时回复，但不能把截图理解结果写入长期 Memory。

4. WakeUp 与 Anchor 边界
   WakeUp 和 Anchor 可以读取后端允许的 Memory 摘要来生成更自然的主动互动。用户暂停或删除后，它们必须尊重新的 Memory 策略，不能从客户端残留状态补记忆。

## 9. UX 约束

1. 不把记忆入口做成主要 MVP 导航。MVP 只需要设置页里的隐私入口和聊天区的暂停状态提示。
2. 删除必须二次确认，确认文案要写明后端异步处理，不承诺立即完成。
3. 暂停状态要可见，但不要打断聊天。聊天输入区提示一行即可。
4. 失败状态要可恢复。用户看到的是重试、稍后查看、联系日志，而不是空白页。
5. 任何记忆卡片或摘要展示都必须来自后端返回的可见字段，不能由客户端拼接隐藏上下文。

## 10. 后续切分

1. MVP：只展示记忆已启用或已暂停状态，不提供复杂记忆浏览。
2. MVP 后第一步：实现暂停和恢复控制。
3. MVP 后第二步：实现全部删除异步任务。
4. 后续版本：实现按时间、按会话、按主题删除，以及后端筛选后的记忆浏览。
