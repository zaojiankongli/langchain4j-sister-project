# AI 女友微信小程序 文本聊天时序流 v1

## 目标
把文本聊天从“用户发消息”到“AI 回复 + TTS + 记忆写入”的全过程写成统一时序，减少前端、后端、AI 编排、记忆服务的理解偏差。

---

## 1. 参与方

- 用户
- 小程序聊天页
- Chat API
- AI 编排层
- Memory 服务
- TTS 服务

---

## 2. 标准时序

### Step 1：用户输入
用户在聊天页输入文本并点击发送。

### Step 2：前端本地回显
聊天页立即插入一条本地用户消息，状态为“已发送 / 等待 AI 回复”。

### Step 3：前端请求聊天接口
前端调用：
`POST /chat/send`

请求体最小内容：
- `content`
- `sessionId`
- 可选 `clientMessageId`

### Step 4：后端做聊天编排
后端顺序：
1. 校验用户身份
2. 读取用户设置
3. 读取关系状态
4. 召回相关记忆
5. 拼装 prompt/context
6. 调模型生成文本回复

### Step 5：后端决定 TTS
若当前策略允许：
1. 把 AI 文本送入 TTS 服务
2. 得到 `audioUrl` 或音频资源标识

### Step 6：后端写入消息与触发记忆提炼
1. 保存用户消息
2. 保存 AI 文本消息
3. 异步或同步触发记忆候选提炼

### Step 7：后端返回统一结果
返回给前端：
- 用户消息正式 ID
- AI 文本消息
- 可选 `audioUrl`
- 可选 `memoryHints`
- 可选关系状态变化摘要

### Step 8：前端更新消息流
前端：
1. 用正式消息替换本地临时消息
2. 插入 AI 回复
3. 若有 `audioUrl`，渲染 AI 音频消息可播放态

### Step 9：前端可选展示记忆提示
若返回 `memoryHints`：
- 以轻提示方式展示，不打断主消息流

---

## 3. 成功条件

一次完整文本聊天最小成功定义：
1. 用户消息本地立即回显
2. AI 有文本回复
3. 若 TTS 开启，则语音可播放
4. 本轮对话被送入记忆流程

---

## 4. 失败分支

### F1：聊天接口失败
- 前端保留用户消息但标记失败
- 提供重试入口

### F2：AI 文本成功但 TTS 失败
- 保留 AI 文本消息
- 不阻断本轮聊天完成
- 音频消息不显示或显示不可播放态

### F3：记忆提炼失败
- 不阻断聊天回复
- 仅影响回忆页和后续命中质量

---

## 5. V1 原则

1. 聊天主链路优先于 TTS。
2. TTS 优先于记忆展示。
3. 记忆提炼失败不能让聊天失败。
