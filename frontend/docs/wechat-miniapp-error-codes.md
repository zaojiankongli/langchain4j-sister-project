# AI 女友微信小程序 接口错误码约定 v1

## 目标
统一前后端错误语义，避免小程序端看到的只是模糊失败文案，或同类错误在不同页面表现不一致。

---

## 1. 通用规则

### 成功
- `code = 200`

### 失败
- 非 200 的 `code` 表示业务错误
- `message` 必须是前端可直接使用的可读文案
- `data` 可为空，但失败时不应依赖 `data.message`

---

## 2. 建议错误码分段

| 范围 | 含义 |
|---|---|
| `4000-4099` | 请求参数 / 通用输入错误 |
| `4100-4199` | 用户与鉴权错误 |
| `4200-4299` | 聊天链路错误 |
| `4300-4399` | TTS 错误 |
| `4400-4499` | 记忆错误 |
| `4500-4599` | Realtime 会话错误 |
| `4600-4699` | 设置与偏好错误 |
| `5000-5099` | 系统内部错误 |

---

## 3. 通用错误码建议

| code | 含义 | 前端处理建议 |
|---|---|---|
| `4001` | 参数缺失 | 直接提示用户修正输入 |
| `4002` | 参数格式错误 | 显示字段级错误或 toast |
| `4101` | 未登录 | 跳登录或刷新登录态 |
| `4102` | 登录态失效 | 清理本地态并回登录 |
| `5001` | 系统繁忙 | 提示稍后再试 |

---

## 4. 聊天错误码建议

| code | 含义 | 前端处理建议 |
|---|---|---|
| `4201` | 聊天请求失败 | 聊天页显示发送失败，可重试 |
| `4202` | 聊天历史拉取失败 | 聊天页显示历史加载失败 |
| `4203` | AI 回复为空 | 给兜底提示，不插入空消息 |

---

## 5. TTS 错误码建议

| code | 含义 | 前端处理建议 |
|---|---|---|
| `4301` | TTS 生成失败 | 保留文本消息，禁用语音播放 |
| `4302` | 音频地址失效 | 提示重新生成或稍后再试 |
| `4303` | 音频播放失败 | 页面 toast，不阻塞继续聊天 |

---

## 6. 记忆错误码建议

| code | 含义 | 前端处理建议 |
|---|---|---|
| `4401` | 记忆提炼失败 | 不阻塞聊天，记录日志 |
| `4402` | 记忆列表拉取失败 | 回忆页提示稍后重试 |
| `4403` | 记忆详情不存在 | 返回列表页并提示 |

---

## 7. Realtime 错误码建议

| code | 含义 | 前端处理建议 |
|---|---|---|
| `4501` | 会话创建失败 | 进入 `error_recoverable` |
| `4502` | 会话中断 | 提供重连或结束按钮 |
| `4503` | provider 超时 | 从 `thinking` 切到可恢复错误态 |
| `4504` | 摘要生成失败 | 不阻塞挂断，提示稍后查看 |

---

## 8. 设置错误码建议

| code | 含义 | 前端处理建议 |
|---|---|---|
| `4601` | 设置读取失败 | 设置页显示兜底文案 |
| `4602` | 设置保存失败 | 设置页保留当前输入并提示重试 |

---

## 9. 前端错误处理原则

1. 错误页和 toast 统一优先使用后端 `message`。
2. 聊天链路错误不应导致整页白屏。
3. TTS 错误不应阻断文本聊天。
4. Realtime 错误应优先可恢复，而不是直接终止体验。
