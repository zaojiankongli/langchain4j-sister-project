# AI 女友微信小程序 开发依赖与阻塞图 v1

## 目的
明确哪些任务可以并行，哪些任务会卡住关键路径，避免团队无效等待或错误排期。

---

## 1. 关键路径

### 主关键路径
`/chat/send` → 聊天页发送链路 → TTS 输出 → 记忆提炼 → 回忆页展示

如果这条链不通，产品主价值不成立。

### 第二关键路径
`/realtime/session/create` → 实时语音页状态机 → `/realtime/session/end` → `/realtime/session/:id/summary`

如果这条链不通，差异化能力不成立。

## 3. 主要阻塞点

### 阻塞 1：聊天接口未定
影响：
- 聊天页真正不可联调
- TTS 与记忆链路都无法验证

### 阻塞 2：TTS 输出方式不确定
影响：
- 前端不知道是从 `/chat/send` 直接拿 `audioUrl`，还是走独立 TTS 接口

### 阻塞 3：记忆提炼规则未落地
影响：
- 回忆页可能有空壳 UI 但没有真实内容
- 聊天中无法体现“她记住了你”

### 阻塞 4：Realtime 供应层接入未验证
影响：
- 实时语音页只能停留在静态 UI
- Live2D 的 speaking/listening 联动无法验证

### 阻塞 5：Live2D 小程序兼容性
影响：
- 实时语音页视觉方案可能需要降级

## 5. 风险优先级

### 高风险
1. Realtime 接入复杂度
2. Live2D 小程序兼容性
3. 记忆提炼质量

### 中风险
1. TTS 播放体验
2. 设置和聊天页联动
3. 首页情绪文案真实感

### 低风险
1. 我的页基础信息
2. 回忆页静态结构
3. 设置页基础表单

---

## 6. 团队协作建议

1. 先让后端锁定聊天/TTS返回结构。
2. 前端同时完成聊天页静态 UI 和消息组件。
3. 记忆与回忆页在聊天链路通后立刻补齐。
4. Realtime 与 Live2D 提前做可行性验证，不要等到最后一周。
